## Context

Major package changes need a durable, user-facing explanation beyond a Changeset summary and generated changelog entry. Establish a release rule that every major Changeset is accompanied by a website blog post.

## Acceptance Criteria

- Release policy defines exactly what qualifies as a major Changeset and when its companion post must be added.
- Each qualifying post explains the behavior change, affected packages, compatibility impact, upgrade steps, and any required user action in plain language.
- Posts use the required `title`, `description`, and `date` frontmatter and are registered in `apps/www/src/blog/posts.ts`.
- Pull request or release validation detects a major Changeset without a corresponding blog post, with an explicit documented exception process for unusual cases.
- Maintainer release documentation, standards, and completion rules include the requirement without treating ordinary patch or minor Changesets as major announcements.
- Website build or route tests verify the post is statically enumerable and renderable.

## Planning Note

Do not add release checks, scripts, or blog posts as part of this planning work.
